# 论文参考模型边缘部署说明

## 一、当前状态

当前 `edge_infer_service` 已经支持两类 ONNX 模型自动识别：

1. 原始 `1D-CNN` 模型：输入形状为 `[N,1,187]`
2. 论文参考模型：输入形状为 `[N,1,17,11]`

当服务检测到论文参考模型时，会在 C++ 推理端自动执行以下前处理：

1. 带通滤波 `0.5Hz ~ 40Hz`
2. `min-max` 归一化
3. `STFT`
4. 构造 `1 x 17 x 11` 输入张量
5. 调用 ONNX Runtime 推理

因此，Qt 客户端和网络协议不需要修改，仍然发送 `187` 个原始心拍点即可。

## 二、当前系统主模型

## 三、Windows 本机运行方式

如果在 Windows 本机直接启动服务，可以使用：

```powershell
F:\graduation_project\build\cpp\Release\edge_infer_service.exe `
  --model F:\graduation_project\artifacts\paper_reference_cnn_full_v1\model_best.onnx `
  --host 0.0.0.0 `
  --port 9000 `
  --sample-dir F:\graduation_project\results\qt_real_samples
```

说明：

- 如果不手动传 `--model`，当前服务默认也会优先使用论文参考模型。
- 启动后日志中会看到：
  - `模型输入模式: paper_reference_stft_2dcnn`
  - `模型输入形状: [-1,1,17,11]` 或类似信息

## 四、香橙派 3 部署步骤

由于你最终运行平台是香橙派 3，所以需要把以下内容同步到板子：

1. 最新 C++ 源码
2. 新的 ONNX 模型文件
3. 重新编译 `edge_infer_service`

### 第一步：同步文件到香橙派

至少要同步这些目录或文件：

- `cpp/`
- `shared/`
- `artifacts/paper_reference_cnn_full_v1/model_best.onnx`

### 第二步：在香橙派重新编译

进入项目目录后，重新执行 `cmake` 和 `build`。

示例：

```bash
cd ~/graduation_project
mkdir -p build/cpp
cd build/cpp
cmake ../../cpp -DONNXRUNTIME_ROOT=/path/to/onnxruntime
cmake --build . --config Release -j2
```

香橙派 3 是 `2GB` 内存，建议：

- `-j2` 或 `-j1`
- 不要开太高并行

### 第三步：启动服务

```bash
./edge_infer_service \
  --model ~/graduation_project/artifacts/paper_reference_cnn_full_v1/model_best.onnx \
  --host 0.0.0.0 \
  --port 9000 \
  --sample-dir ~/graduation_project/results
```

如果你的样本目录实际在 `results/qt_real_samples`，就把 `--sample-dir` 改成那个目录。

## 五、为什么 Qt 端不用改

因为当前改动放在边缘端推理服务内部。

Qt 客户端仍然发送：

- `PREDICT f1,f2,...,f187`
- 或 `PLAY_SAMPLE name.txt`

服务端收到后，会自动判断当前加载的 ONNX 模型属于哪种输入类型：

- 1D 模型：直接推理
- 论文参考模型：先前处理再推理

所以 Qt 界面层和网络层不需要重新设计。
