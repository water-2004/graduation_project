# 监测记录与报警模块技术说明

## 1. 模块目标

本模块用于把心电推理结果从“界面展示”升级为“业务数据留痕”。

在当前系统中，推理结果不再只停留在 Qt 界面上，而是会进一步进入业务服务端，形成两类数据：

1. 监测记录
2. 报警记录

这样做的目的有三点：

1. 让系统具备可追溯性，后续可以查询某个病人的历史监测结果。
2. 让异常结果进入报警链路，而不是仅在前端颜色变化后丢失。
3. 为后续历史记录页面、报警处理页面、数据库查询与筛选打基础。

## 2. 当前业务链路

当前链路如下：

1. Qt 客户端连接推理服务 `edge_infer_service`
2. Qt 客户端拿到推理结果或样本播放结果
3. `InferPage` 自动构造监测记录对象 `MonitorRecordInfo`
4. Qt 客户端通过 `BusinessClient` 将监测记录发送到 `business_service`
5. `business_service` 将监测记录写入 `business_service.db` 中的 `monitor_records` 表
6. 如果 `alert_level` 为 `warning` 或 `critical`，业务服务端自动生成报警记录并写入 `business_service.db` 中的 `alerts` 表
7. 病人管理页可按病人维度查询监测记录和报警记录

## 4. 业务服务端实现

### 4.1 SQLite 仓库扩展

文件：

- `cpp/src/business/file_repository.h`
- `cpp/src/business/file_repository.cpp`

当前运行时持久化对象：

1. `business_service.db`
2. 其中的 `monitor_records` 和 `alerts` 表

新增方法：

1. `AddMonitorRecord`
2. `ListMonitorRecords`
3. `ListAlerts`

关键行为：

1. 新增监测记录时，先校验病人是否存在。
2. 监测记录由服务端自动补齐记录时间和记录编号。
3. 告警等级为 `warning` 或 `critical` 时，服务端自动生成报警记录。
4. 删除病人时，会同步清理该病人的监测记录与报警记录。

### 4.2 业务协议扩展

文件：`cpp/src/business/business_logic.cpp`

新增协议命令：

1. `ADD_MONITOR_RECORD`
2. `LIST_MONITOR_RECORDS`
3. `LIST_ALERTS`

新增响应前缀：

1. `RECORD_OK`
2. `MONITOR_RECORDS`
3. `ALERTS`

协议示例：

```text
ADD_MONITOR_RECORD P001|V|0.9821|critical|4.51|sample_playback|label_4_sample.txt|V
```

返回：

```text
RECORD_OK 监测记录已保存，并生成报警记录
```

查询监测记录：

```text
LIST_MONITOR_RECORDS P001
```

查询报警记录：

```text
LIST_ALERTS P001
```

新增信号：

2. `sig_monitor_records_ready`
3. `sig_alerts_ready`

### 5.2 监测页自动上报

文件：

- `widget/graduation_project_widget/inferpage.h`
- `widget/graduation_project_widget/inferpage.cpp`

当前行为：

1. 手动输入 187 维特征后得到推理结果，自动上报业务服务端。
2. 播放 MIT-BIH 样本后得到推理结果，自动上报业务服务端。
3. 监测页顶部仍显示当前病人信息。
4. 告警等级为 `warning` 时写日志提示。
5. 告警等级为 `critical` 时，除了界面红色提示外，还会弹出告警消息框。

这里的关键设计是：

推理服务只负责推理，业务服务端只负责保存和管理，这样职责边界比较清楚。

### 5.3 病人管理页增加记录视图

- `widget/graduation_project_widget/patient_page.h`
- `widget/graduation_project_widget/patient_page.cpp`

新增内容：

1. 监测记录表
2. 报警记录表
3. 选中病人后自动查询对应历史数据

这样病人页现在不仅能维护病人信息，还能查看该病人的业务记录。

## 6. 主窗口调度关系

文件：`widget/graduation_project_widget/mainwindow.cpp`

当前主窗口新增了三组连接：

1. 病人页到业务服务端的记录查询连接
2. 监测页到业务服务端的监测记录保存连接
3. 业务服务端回包到病人页和监测页的结果回填连接

主窗口本身仍然只负责调度，不直接处理业务协议。

业务数据目录中的在线主存储现在是：

- `business_service.db`

其中核心表包括：

1. `users`
2. `patients`
3. `monitor_records`
4. `alerts`

说明：

当前模块已经切换为 SQLite 在线持久化，Qt 页面和业务协议保持不变。旧版 TSV 仅在首次启动时作为兼容导入来源，不再是在线主存储。
