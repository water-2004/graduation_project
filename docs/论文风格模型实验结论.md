## 关键分析

本次论文风格模型有一个很明显的特点：

- `Macro-Recall` 很高，说明它对异常类并不迟钝。
- 但 `Macro-F1` 不高，说明它虽然能抓到异常，但误报较多。

从分类报告看，问题主要出在类别 `1` 和类别 `3`：

- 类别 `1`：Precision 只有 `0.4629`
- 类别 `3`：Precision 只有 `0.2219`

这说明模型把不少原本不属于这些类别的样本，也误判成了这两个异常类。

因此，这个模型的现阶段特点可以概括为：

“敢报异常，但报得不够准。”

## 为什么会这样

主要原因有三点：

1. 当前输入仍然是本项目已有的 `187` 点单拍数据，而不是论文中的 `10` 秒滑动窗口。
2. 当前还没有加入论文中的 `SMOTE`、剪枝、量化等完整流程。
3. STFT + 2D-CNN 这条路线更依赖输入表示方式，直接套到单拍数据上，效果不一定优于树模型。

## 当前可得出的严谨结论

1. 当前项目已经完成工程闭环。
2. 在当前 MIT-BIH 数据处理方式下，`Random Forest` 是综合指标最好的模型。
3. `XGBoost` 也明显优于当前部署的 `1D-CNN`。
4. 论文风格 `STFT + 2D-CNN` 已经完成第一版近似复现，并验证链路可运行。
5. 但在目前这套数据表示与训练配置下，它还不是最优模型。

## 下一步建议

1. 如果目标是先完成毕业设计答辩，建议先以 `Random Forest / XGBoost` 作为“实验最优模型”结论。
2. 如果目标是更贴近论文，下一步应继续改进论文风格模型，包括：`10` 秒窗口、SMOTE、剪枝、量化。
3. 如果目标是落地到边缘端现有系统，则需要再评估：树模型是否转 ONNX，或者继续优化当前 1D-CNN / 论文风格 CNN。
