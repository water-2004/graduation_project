# Qt 桌面端说明

## 1. 模块定位

`widget/graduation_project_widget` 是你的桌面演示端，不负责训练模型，主要负责：

- 连接边缘推理服务
- 发送心跳命令 `PING`
- 发送一条 `PREDICT` 推理请求
- 展示服务端返回的预测类别、置信度、告警等级和耗时

它在毕设里的位置可以理解为：

`Qt 桌面端 -> 边缘推理服务 -> ONNX 模型`

## 2. 当前客户端架构

这一版已经按照你给的 `F:\QTproject\chat` 项目的思路做了分层，不再把网络逻辑直接写在主窗口里。

当前结构是：

- `MainWindow`
  - 只负责主窗口壳层和页面承载
- `InferPage`
  - 负责界面展示、按钮交互、输入校验、结果显示
- `TcpMgr`
  - 负责 TCP 连接、命令发送、响应解析、信号分发
- `global.h`
  - 定义页面层和网络层共用的数据结构
- `singleton.h`
  - 提供和参考项目类似的单例模板

也就是：

`MainWindow -> InferPage -> TcpMgr -> edge_infer_service`

## 3. 为什么这样分层

这样写的好处是：

- 主窗口职责单一，后面加新页面更方便
- 页面层不直接接触 `QTcpSocket`，更容易维护
- 网络逻辑集中在 `TcpMgr`，协议修改时影响范围更小
- 结构上和你参考的聊天项目更接近，便于你学习和复用

## 4. 当前协议

Qt 端目前直接复用你已经写好的文本协议：

- `PING`
- `PREDICT f1,f2,...,f187`
- `QUIT`

服务端返回示例：

```text
PONG
OK pred=2 conf=0.973421 alert=critical latency_ms=4.186
BYE
ERR 特征数量错误，期望 187，实际 120
```

## 5. 当前界面功能

目前已经实现：

- 服务器 IP 输入
- 端口输入
- 连接 / 断开
- 发送 `PING`
- 输入 187 维特征后发送 `PREDICT`
- 一键填充演示特征，便于联调网络链路
- 日志窗口
- 结果展示区

## 6. 你在 Qt Creator 里如何运行

建议使用套件：

- `Desktop Qt 6.8.3 MSVC2022 64bit`

操作步骤：

1. 用 Qt Creator 打开 `F:\graduation_project\widget\graduation_project_widget\CMakeLists.txt`
2. 选择 `Desktop Qt 6.8.3 MSVC2022 64bit`
3. 点击“配置项目”
4. 直接构建并运行

## 7. 联调方式

先启动边缘服务，再启动 Qt 桌面端。

边缘服务启动后，Qt 端默认连接：

- IP：`127.0.0.1`
- 端口：`9000`

联调顺序建议：

1. 点击“连接服务器”
2. 点击“发送 PING”，确认收到 `PONG`
3. 点击“填充演示数据”
4. 点击“发送预测”
5. 查看日志区和结果区
