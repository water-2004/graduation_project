# 业务服务端运行说明

## 1. 当前模块用途

当前 `business_service` 已经是系统中的正式业务服务端，主要用于：

1. 登录校验。
2. 病人信息管理。
3. 监测记录保存与查询。
4. 报警记录生成、查询与确认。
5. 为 Qt 客户端提供统一业务接口。
6. 运行时直接写入 SQLite 数据库。

## 2. 构建目标

当前 C++ 工程中的业务服务目标为：

- `business_service`

## 3. Windows 下编译

在已有 `build/cpp` 目录下执行：

```powershell
cmake --build F:\graduation_project\build\cpp --config Release --target business_service
```

## 4. 启动方式

### 4.1 默认启动

```powershell
F:\graduation_project\build\cpp\Release\business_service.exe
```

默认参数：

1. 监听地址：`0.0.0.0`
2. 端口：`9200`
3. 数据目录：`data/business_service`

### 4.2 自定义启动

```powershell
F:\graduation_project\build\cpp\Release\business_service.exe `
  --host 127.0.0.1 `
  --port 9200 `
  --data-dir F:\graduation_project\data\business_service `
  --log-dir F:\graduation_project\build\cpp\Release\logs_business_service
```

## 5. 启动后会生成什么

在数据目录下，当前会生成或使用：

1. `business_service.db`
2. `logs/` 或你指定的日志目录

如果是兼容旧版本数据，服务首次启动时还会读取同目录下可能存在的：

1. `users.tsv`
2. `patients.tsv`
3. `monitor_records.tsv`
4. `alerts.tsv`

这些 `TSV` 文件现在只是迁移来源，不再是在线主存储。

## 6. 默认管理员账号

首次启动会自动生成默认管理员账号：

- 用户名：`admin`
- 密码：`123456`

## 7. 协议命令示例

### 7.1 心跳测试

```text
PING
```

响应：

```text
PONG
```

### 7.2 登录

```text
LOGIN admin 123456
```

响应示例：

```text
LOGIN_OK role=admin display_name=系统管理员
```

### 7.3 添加病人

```text
ADD_PATIENT P001|张三|男|21|13800000000|首次建档
```

响应：

```text
OK 病人已添加
```

### 7.4 修改病人信息

```text
UPDATE_PATIENT P001|张三-复诊|男|22|13900000000|复诊后更新信息
```

响应示例：

```text
OK 病人信息已更新
```

### 7.5 查询病人列表

```text
LIST_PATIENTS
```

响应示例：

```text
PATIENTS P001|张三-复诊|男|22|13900000000|复诊后更新信息
```

### 7.6 写入监测记录

```text
ADD_MONITOR_RECORD P001|V|0.95|critical|18.3|qt_manual|sample_a|V
```

响应示例：

```text
RECORD_OK 监测记录已保存，并生成报警记录
```

### 7.7 查询病人维度报警记录

```text
LIST_ALERTS P001
```

### 7.8 查询全局报警记录

```text
LIST_ALL_ALERTS
```

### 7.9 确认报警

```text
CONFIRM_ALERT AL2026_03_26_19_27_13_0001|admin
```

响应示例：

```text
ALERT_OK 报警已确认
```

## 8. 本次已验证结果

我在 `2026-03-26` 做过一轮实际冒烟验证，验证流程如下：

1. 编译 `business_service`。
2. 启动服务。
3. 登录默认管理员。
4. 新增病人 `P100`。
5. 修改病人信息 `P100`。
6. 写入一条 `critical` 监测记录。
7. 查询 `LIST_ALL_ALERTS`。
8. 直接查询 SQLite 数据库文件。

验证结果：

```text
UPDATE_PATIENT => OK 病人信息已更新
LIST_ALL_ALERTS => ALL_ALERTS ...|P201|...|critical|...|new||
SQLite 查询结果 => P100|张三已修改|22|13900139000|修改后备注
生成文件 => business_service.db
```

这说明病人修改已经真正写入 SQLite，而不是只停留在前端界面。

## 9. 当前限制

当前版本仍然存在以下限制：

1. 病人编号作为主键，当前编辑模式下不支持直接改编号。
2. 登录仍是明文密码。
3. 协议仍是纯文本协议，未加密。
4. 仍是单机版业务服务，不涉及多端并发同步方案。
