# 业务服务线程池化技术说明

## 1. 模块定位

本改进将业务服务端 `business_service` 的网络层从"每连接一线程"模式升级为基于 `Boost.Asio` 的 `IOContextPool + TcpServer` 异步模型，消除线程泄漏风险，提升并发处理能力。

## 2. 改进前的问题

原 `business_service_main.cpp` 采用以下模式：

1. 主线程 `accept()` 阻塞等待连接。
2. 每接受一个连接，`std::thread(&HandleSession, socket).detach()`。
3. 分离的线程在连接关闭后自行退出。

问题：

- `detach()` 导致线程不受管理，无法优雅关停。
- 短连接场景下频繁创建/销毁线程开销大。
- 无法控制最大并发数。

## 3. 改进方案

### 3.1 LogicHandler 接口抽象

新增 `net/logic_handler.h`，定义抽象接口：

```cpp
class LogicHandler {
public:
    virtual ~LogicHandler() = default;
    virtual std::string HandleLine(const std::string& line, bool* close_conn) const = 0;
};
```

`LogicSystem`（推理端）和 `BusinessLogic`（业务端）均继承此接口，使 `TcpServer` / `TcpSession` 可以复用同一套网络代码。

### 3.2 IOContextPool

文件：`net/io_context_pool.h`、`net/io_context_pool.cpp`

职责：

1. 创建 N 个 `boost::asio::io_context`，每个绑定一个工作线程。
2. 轮询分配新连接到不同的 `io_context`（Round-Robin）。
3. 提供 `Run()` / `Stop()` 控制生命周期。

### 3.3 TcpServer

文件：`net/tcp_server.h`、`net/tcp_server.cpp`

职责：

1. 在指定端口上异步 `accept` 连接。
2. 每个新连接创建一个 `TcpSession`，分配到池中的 `io_context`。
3. 将 `LogicHandler` 传递给每个 `TcpSession`。

### 3.4 TcpSession

文件：`net/tcp_session.h`、`net/tcp_session.cpp`

职责：

1. 异步读取以 `\n` 分隔的文本命令。
2. 调用 `LogicHandler::HandleLine()` 处理命令。
3. 异步写回响应。
4. 当 `close_conn` 为 true 时关闭连接。

### 3.5 业务服务入口重构

文件：`business/business_service_main.cpp`

改动：

1. 删除 `HandleSession()` 函数和 `#include <thread>`。
2. 使用 `IOContextPool` + `TcpServer` 替代手动线程管理。
3. 新增 `--threads` 启动参数（默认 4 线程）。
4. 注册 `SIGINT` / `SIGTERM` 信号处理优雅关停。

## 5. 当前版本的意义

```text
业务服务端网络层升级为 Boost.Asio 异步线程池模型，通过 LogicHandler 接口抽象实现了推理端与业务端共用同一套 TcpServer/TcpSession 网络基础设施，消除了 detach 线程泄漏风险，支持可配置的线程数量与优雅关停。
```
