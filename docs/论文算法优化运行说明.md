# 论文算法优化运行说明

## 1. 模块作用

本模块包含两个脚本：

1. `scripts/11_train_paper_optimized.py`：在参考论文 CNN 基础上进行优化训练。
2. `scripts/12_compare_all_models.py`：对所有已训练模型进行全量对比分析。

运行完成后，你可以得到：

1. 优化后的模型文件（`.pt` 和 `.onnx`）
2. 完整的训练指标和日志
3. 全量模型对比报告

## 2. 前置条件

需要以下环境和数据：

1. Python 3.10+
2. 依赖包：`torch`, `numpy`, `pandas`, `scikit-learn`, `imbalanced-learn`, `scipy`
3. MIT-BIH 数据集文件：`MIT-BIH/mitbih_train.csv` 和 `MIT-BIH/mitbih_test.csv`
4. 已有模型的 `metrics.json`（用于对比脚本）

## 3. 训练脚本运行

### 3.1 默认参数运行

```powershell
python scripts/11_train_paper_optimized.py
```

默认配置：

- 训练 80 轮
- 批大小 128
- 学习率 1e-3
- 权重衰减 1e-4
- Dropout 0.3
- 调度器 patience=5, factor=0.5
- 输出到 `artifacts/paper_optimized_cnn/`

### 3.2 自定义参数运行

```powershell
python scripts/11_train_paper_optimized.py ^
    --epochs 100 ^
    --batch-size 256 ^
    --lr 5e-4 ^
    --weight-decay 5e-4 ^
    --dropout-rate 0.4 ^
    --scheduler-patience 8 ^
    --scheduler-factor 0.3 ^
    --output-dir artifacts/paper_optimized_cnn_v2
```

### 3.3 快速验证（冒烟测试）

```powershell
python scripts/11_train_paper_optimized.py --epochs 2
```

用于验证脚本能正常运行并生成所有输出文件。

### 3.4 训练产物

运行结束后，输出目录包含：

```text
artifacts/paper_optimized_cnn/
├── model_best.pt               # PyTorch 模型
├── model_best.onnx             # ONNX 模型
├── metrics.json                # 训练指标
├── train_log.csv               # 逐轮日志
├── classification_report.txt   # 分类报告
├── confusion_matrix.csv        # 混淆矩阵
└── 训练报告.md                  # 中文报告
```

## 4. 对比脚本运行

### 4.1 全量对比（6个模型）

```powershell
python scripts/12_compare_all_models.py ^
    --metrics "1D-CNN:artifacts/cnn_mitbih_v2/metrics.json" ^
              "Random Forest:artifacts/random_forest_mitbih_full/metrics.json" ^
              "XGBoost:artifacts/xgboost_mitbih_full/metrics.json" ^
              "论文风格CNN:artifacts/paper_style_cnn_full_v1/metrics.json" ^
              "参考论文CNN:artifacts/paper_reference_cnn_full_v1/metrics.json" ^
              "优化后论文CNN:artifacts/paper_optimized_cnn/metrics.json" ^
    --baseline-name "参考论文CNN" ^
    --optimized-name "优化后论文CNN"
```

### 4.2 部分对比（不含优化前后分析）

如果只想对比部分模型，不需要 `--baseline-name` 和 `--optimized-name`：

```powershell
python scripts/12_compare_all_models.py ^
    --metrics "Random Forest:artifacts/random_forest_mitbih_full/metrics.json" ^
              "参考论文CNN:artifacts/paper_reference_cnn_full_v1/metrics.json" ^
              "优化后论文CNN:artifacts/paper_optimized_cnn/metrics.json"
```

### 4.3 对比产物

```text
artifacts/model_compare_all/
├── comparison.json     # 结构化对比数据
└── 模型对比报告.md      # 中文对比报告（5个章节）
```

## 5. 边缘端部署替换步骤

如果优化后模型指标优于当前部署模型，可替换 ONNX 文件：

1. 确认训练产物中的 `model_best.onnx` 存在且无导出错误。

2. 将 ONNX 文件复制到 `edge_infer_service` 的模型目录：

```powershell
copy artifacts\paper_optimized_cnn\model_best.onnx data\models\model_best.onnx
```

3. 重启 `edge_infer_service`，观察日志确认加载模式：

```text
输入模式: paper_reference_stft_2dcnn
```

4. 通过 Qt 客户端执行一次推理，验证结果正常。

说明：

优化后模型与基线模型的输入形状完全一致（`[1,1,17,11]`），C++ 推理引擎会自动检测 rank=4 并走 STFT 前处理路径，无需修改任何 C++ 或 Qt 代码。

## 6. 常见问题

### 6.1 训练时间过长

80 轮全量训练在 CPU 上可能需要较长时间。建议：

1. 先用 `--epochs 2` 做冒烟测试。
2. 如果有 GPU，脚本会自动检测并使用 CUDA。
3. 观察 `train_log.csv` 中验证指标是否已收敛，适时中断。

### 6.2 ONNX 导出失败

如果 `metrics.json` 中 `onnx_export_error` 不为空：

1. 检查 PyTorch 版本是否支持 opset 13。
2. 确认 `model_best.pt` 文件完整。
3. 可手动重新导出。

### 6.3 对比脚本报错找不到文件

确认 `--metrics` 参数中的路径是否正确，格式为 `模型名:路径`，冒号前后不要有多余空格。

### 6.4 Macro-F1 没有提升

可能的调参方向：

1. 增加 `--epochs`（如 120）
2. 调低 `--scheduler-factor`（如 0.3）
3. 增大 `--scheduler-patience`（如 8）
4. 尝试不同的 `--dropout-rate`（如 0.4 或 0.5）
5. 增大 `--weight-decay`（如 5e-4）
