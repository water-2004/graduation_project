# 系统完善开发计划

## 1. 当前项目状态

当前项目已经完成以下核心能力：

1. MIT-BIH 数据预处理与模型训练
2. 参考文献路线模型训练与 ONNX 导出
3. 边缘端 C++ 推理服务
4. Qt 客户端实时波形显示与基础通信
5. 香橙派 3 边缘端运行链路
6. 模拟采集样本播放与预测结果展示

当前缺失的部分主要集中在“业务系统层”：

1. 登录与用户管理
2. 病人信息管理
3. 监测记录持久化
4. 告警机制与告警记录
5. 历史记录查询
6. 前端页面完整性

因此，后续不再大改现有核心链路，而是按照“先补业务骨架，再补前端页面，最后联调整体闭环”的顺序推进。

## 2. 总体开发原则

后续模块按以下原则推进：

1. 每次只完成一个明确模块，不并行开过多功能。
2. 每个模块都必须包含：代码、中文注释、技术文档、运行说明。
3. 代码风格统一采用 Google 风格。
4. 新增模块优先保持最小可运行版本，避免一次做得过重。
5. 不推翻现有 Qt 与边缘推理链路，只在其上扩展业务能力。

## 3. 系统后续划分

后续系统统一划分为三个端：

### 3.1 Qt 客户端

职责：

- 登录
- 病人管理
- 实时监测
- 告警展示
- 历史记录查询

### 3.2 香橙派边缘推理端

职责：

- 接收 ECG 原始数据或模拟样本
- 执行论文参考模型前处理
- ONNX 推理
- 返回预测结果与告警级别

### 3.3 业务服务端

职责：

- 用户登录认证
- 病人信息管理
- 监测会话管理
- 推理结果保存
- 告警记录保存
- 历史数据查询

## 4. 详细阶段安排

## 阶段一：业务服务端基础骨架

目标：把“数据保存”和“业务接口”先立起来。

本阶段要完成：

1. 业务服务端目录结构
2. SQLite 数据库设计
3. 数据访问层
4. 用户表、病人表、监测会话表、告警表
5. 基础 TCP/JSON 协议定义
6. 服务端启动与配置文件

本阶段交付物：

- C++ 服务端骨架代码
- SQLite 初始化脚本或初始化逻辑
- 《业务服务端设计说明》
- 《数据库设计说明》

## 阶段二：登录模块

目标：先把前端入口做完整。

本阶段要完成：

1. Qt 登录页面
2. 登录请求发送
3. 服务端登录接口
4. 登录结果处理
5. 基础用户角色字段

本阶段交付物：

- Qt 登录界面代码
- 服务端登录处理代码
- 《登录模块技术说明》

## 阶段三：病人管理模块

目标：把监测对象和系统记录关联起来。

本阶段要完成：

1. 病人列表页面
2. 新增病人
3. 编辑病人
4. 删除病人
5. 查询病人
6. Qt 与业务服务端交互

本阶段交付物：

- 病人管理前后端代码
- 《病人管理模块技术说明》

## 阶段四：监测会话与实时记录保存

目标：把实时推理与病人绑定起来。

本阶段要完成：

1. 选择病人后开始监测
2. 创建监测会话
3. 保存实时推理结果摘要
4. 保存心率、预测类别、置信度、告警级别
5. 支持结束监测会话

本阶段交付物：

- 监测会话代码
- 推理结果保存代码
- 《监测会话与记录模块说明》

## 阶段五：告警机制

目标：让系统具备更完整的医疗监测表现。

本阶段要完成：

1. 模型异常告警
2. 心率阈值告警
3. 连续异常判定
4. 告警记录保存
5. Qt 告警展示与确认

建议的最小规则：

- `pred != 0` 且 `confidence >= threshold` 触发模型异常告警
- 心率小于 `50` 或大于 `120` 触发阈值告警
- 连续多次异常升级为严重告警

本阶段交付物：

- 告警判定代码
- 告警 UI 代码
- 《告警机制设计说明》

## 阶段六：历史记录查询

目标：让系统从“实时演示”提升为“可查询系统”。

本阶段要完成：

1. 监测历史列表
2. 告警历史列表
3. 按病人查询

5. 基础详情页

本阶段交付物：

- 查询界面代码

## 阶段七：系统收尾与答辩准备

目标：补工程细节和答辩展示材料。

本阶段要完成：

1. 配置文件整理
2. 日志分类整理
3. 异常处理补全
4. 香橙派实机运行截图和日志

## 5. 当前推荐执行顺序

从现在开始，严格按下面顺序推进：

1. 业务服务端基础骨架
2. 登录模块
3. 病人管理模块
4. 监测会话与数据保存
5. 告警机制
6. 历史记录查询
7. UI 打磨与答辩材料

## 6. 当前第一优先级

当前最先实现的模块是：

- 业务服务端基础骨架

原因：

1. 登录、病人管理、历史记录都依赖后端数据存储。
2. 如果没有后端骨架，Qt 页面写出来也只是空壳。
3. 该模块完成后，后续功能可以持续叠加，不会返工。

## 7. 后续执行方式

从当前开始，后续每完成一个模块，都必须同步完成：

1. 代码实现
2. 中文注释
3. 对应 `md` 技术文档
4. 构建/运行说明
5. 阶段结果总结

这份文档作为后续系统完善的总路线图，后续默认按此执行，除非用户明确调整优先级。
