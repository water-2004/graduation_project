# 编码规范与模块交付约定

## 1. 适用范围

本约定适用于当前毕业设计项目中的以下代码：

1. C++ 服务端代码
2. C++ 边缘推理端代码
3. Qt 客户端代码
4. Python 训练与数据处理脚本
5. 所有新增技术文档

## 2. 总体规范

后续新增代码与文档统一遵循以下原则：

1. 默认使用中文注释。
2. 默认使用 UTF-8 编码。
3. 注释要求简洁、准确，不写废话注释。
4. 每个模块完成后必须补 `md` 文档。
5. 每次改动优先保持小步提交、可回退、可验证。

## 3. C++ 代码风格

C++ 代码统一参考 Google C++ Style Guide，具体采用以下落地规则：

### 3.1 命名规则

1. 类型名使用大驼峰：`PatientService`
2. 函数名使用大驼峰：`LoadPatientList()`
3. 变量名使用小写下划线或已有项目一致风格
4. 成员变量以下划线结尾：`socket_`
5. 常量使用 `k` 前缀：`kDefaultPort`

### 3.2 头文件与实现文件

1. 接口放 `.h`
2. 实现放 `.cpp`
3. 一个模块尽量职责单一
4. 公共接口写清楚注释说明

### 3.3 注释要求

1. 类注释说明职责
2. 关键函数说明输入、输出、行为
3. 复杂逻辑前补短注释
4. 禁止逐行翻译式注释

### 3.4 代码组织

1. 配置、协议、数据访问、业务逻辑、网络层分开
2. 不把数据库逻辑直接塞进网络会话类
3. 不把 UI 逻辑直接塞进 Qt 网络管理类

## 4. Qt 代码风格

Qt 客户端统一要求：

1. 页面类按功能拆分
2. 页面与网络逻辑尽量解耦
3. UI 控件命名清晰
4. 事件槽函数只负责界面交互，不直接堆复杂业务逻辑
5. 与服务端交互尽量通过单独的管理类封装

## 5. Python 脚本规范

1. 中文注释
2. 参数可命令行配置
3. 输出目录清晰
4. 指标结果写入 `json` 和 `md`
5. 训练脚本必须保留关键实验参数

## 6. 文档规范

每个模块完成后，必须至少补一份对应文档。

文档统一建议包含以下部分：

1. 模块目标
2. 模块职责
3. 核心类/文件说明
4. 数据流或调用流程
5. 关键设计点
6. 运行方式
7. 已知限制

## 7. 模块交付标准

一个模块只有在满足以下条件后，才算完成：

1. 代码实现完成
2. 构建通过或脚本可运行
3. 关键功能联调通过
4. 中文注释已补齐
5. `md` 技术文档已补齐
6. 已记录下一步待改进项

## 8. 当前约定的优先级

从现在开始，后续开发默认按以下优先级执行：

1. 先保证功能闭环
2. 再补业务完整性
3. 再做 UI 细化与体验优化

## 9. 当前执行承诺

后续我在这个项目里新增或修改模块时，默认遵守以下要求：

1. 代码尽量遵循 Google 风格
2. 注释使用中文
3. 每个模块都配套 `md` 技术文档
4. 每次只推进一个清晰模块
5. 阶段结果会明确告诉你做到哪一步
