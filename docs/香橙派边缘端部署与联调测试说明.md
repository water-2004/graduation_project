# 香橙派边缘端部署与联调测试说明

## 1. 文档目的

本文档用于指导当前毕设系统完成以下工作：

1. 将边缘推理端部署到香橙派 3。
2. 在 Windows 主机上启动业务服务端与 Qt 客户端。
3. 逐项联调系统功能。
4. 记录每一步的预期结果，便于答辩前自测和老师验收。

本文档默认你的系统架构如下：

1. 香橙派 3：运行 `edge_infer_service`
2. Windows 主机：运行 `business_service`
3. Windows 主机：运行 Qt 客户端 `graduation_project_widget`

## 2. 当前联调目标

本轮联调的目标不是“继续开发新功能”，而是确认当前系统已经具备完整闭环：

1. Qt 可以连接业务服务端。
2. Qt 可以连接香橙派上的边缘推理服务。
3. Qt 可以发起样本推理。
4. 推理结果可以显示在界面中。
5. 监测记录可以保存到业务服务端。
6. 异常结果可以生成报警。
7. 报警可以在报警中心查看和确认。
8. 总览页可以展示统计结果。
9. 密码修改功能可用。
10. 推理连接断开后可自动重连。

## 3. 测试环境

建议测试环境如下：

### 3.1 硬件

1. Windows 开发主机 1 台
2. 香橙派 3（2GB）1 台
3. 主机与香橙派处于同一局域网

### 3.2 软件

Windows 主机：

1. Qt Creator / Qt 6
2. 已编译好的 `business_service`
3. 已编译好的 Qt 客户端

香橙派：

1. Linux 系统
2. CMake
3. GCC / G++
4. ONNX Runtime ARM 版本
5. 已同步项目源码与模型文件

## 4. 联调前准备

### 4.1 需要同步到香橙派的内容

至少保证以下内容已经上传到香橙派项目目录：

1. `cpp/`
2. `shared/`
3. `artifacts/paper_reference_cnn_full_v1/model_best.onnx`
4. `results/qt_real_samples/`

如果你已经把项目整体目录上传过去，也可以直接使用。

### 4.2 香橙派上建议的目录结构

示例：

```text
~/graduation_project
├─ cpp/
├─ shared/
├─ artifacts/
│  └─ paper_reference_cnn_full_v1/
│     └─ model_best.onnx
├─ results/
│  └─ qt_real_samples/
└─ build/
   └─ cpp/
```

### 4.3 Windows 主机上准备内容

1. `business_service.exe` 已经可运行
2. Qt 客户端已编译通过
3. 已知道香橙派在局域网中的 IP 地址

## 5. 第一步：在香橙派编译边缘推理服务

进入香橙派项目目录：

```bash
cd ~/graduation_project
mkdir -p build/cpp
cd build/cpp
```

执行 CMake 配置：

```bash
cmake ../../cpp -DONNXRUNTIME_ROOT=/path/to/onnxruntime
```

执行编译：

```bash
cmake --build . --config Release -j2
```

说明：

1. 香橙派 3 是 `2GB` 内存，建议使用 `-j2` 或 `-j1`
2. 如果内存紧张，不要开太高并行度

### 5.1 编译成功的判定标准

编译完成后，能够在构建目录中看到：

```text
edge_infer_service
```

或：

```text
edge_infer_service.exe
```

具体取决于你板子上的平台和构建结果。

## 6. 第二步：在香橙派启动边缘推理服务

进入编译输出目录后启动：

```bash
./edge_infer_service \
  --model ~/graduation_project/artifacts/paper_reference_cnn_full_v1/model_best.onnx \
  --host 0.0.0.0 \
  --port 9000 \
  --sample-dir ~/graduation_project/results/qt_real_samples
```

### 6.1 启动成功的判定标准

日志中应能看到类似信息：

1. 服务准备启动
2. 模型路径正确
3. 监听地址为 `0.0.0.0:9000`
4. 已加载样本数量大于 0
5. 服务已启动，等待客户端连接

### 6.2 如果启动失败，优先检查

1. `model_best.onnx` 路径是否正确
2. `--sample-dir` 路径是否正确
3. ONNX Runtime 是否安装正确
4. 端口 `9000` 是否被占用

## 7. 第三步：在 Windows 主机启动业务服务端

运行：

```powershell
F:\graduation_project\build\cpp\Release\business_service.exe --host 0.0.0.0 --port 9200
```

### 7.1 启动成功的判定标准

日志中应能看到：

1. 业务服务启动成功
2. 监听地址 `0.0.0.0:9200`
3. SQLite 数据库路径
4. 默认管理员账号 `admin / 123456`

## 8. 第四步：启动 Qt 客户端

在 Qt Creator 中运行 `graduation_project_widget`，或者直接运行构建出的可执行文件。

启动后先不要急着测试全部功能，按下面步骤逐项验证。

## 9. 联调测试步骤

下面的每一步都建议记录：

1. 操作步骤
2. 实际结果
3. 是否通过
4. 如果失败，失败现象是什么

### 9.1 测试 1：业务服务登录

操作：

1. 打开 Qt 客户端登录页
2. 输入业务服务端地址：Windows 主机 IP 或 `127.0.0.1`
3. 端口填写：`9200`
4. 用户名填写：`admin`
5. 密码填写：`123456`
6. 点击登录

预期结果：

1. 登录成功
2. 进入主界面
3. 左侧侧边栏可用
4. 不出现连接失败提示

判定：

1. 能进入系统主界面，记为通过
2. 若提示连接超时或用户名密码错误，记为失败

### 9.2 测试 2：总览页数据刷新

操作：

1. 登录成功后进入总览页
2. 观察页面是否自动刷新

预期结果：

1. 病人数量卡片正常显示
2. 监测记录数量正常显示
3. 报警数量正常显示
4. 最近监测记录表和最近报警表可展示数据

判定：

1. 页面有正常统计值，记为通过
2. 页面一直为空但业务端已有数据，记为失败

### 9.3 测试 3：病人管理功能

操作：

1. 进入病人管理页
2. 新增一个测试病人，例如：
   - 病人编号：`P9001`
   - 姓名：`联调测试病人`
   - 性别：`男`
   - 年龄：`25`
   - 电话：`13800000000`
   - 备注：`联调测试`
3. 保存后刷新列表
4. 再修改该病人的部分信息

预期结果：

1. 新增成功
2. 列表中可以看到该病人
3. 修改后内容正确更新
4. 删除功能也可正常使用

### 9.4 测试 4：Qt 连接香橙派上的边缘推理服务

操作：

1. 进入推理监测页
2. 输入香橙派 IP 地址
3. 端口填写：`9000`
4. 点击连接

预期结果：

1. 显示连接成功
2. 日志区能看到已连接到服务器
3. 若点击 `PING`，能收到 `PONG`

### 9.5 测试 5：获取样本列表

操作：

1. 在推理页点击“加载样本列表”

预期结果：

1. 样本下拉框中出现样本文件名
2. 日志中出现 `LIST_SAMPLES` 请求和 `SAMPLES` 响应

### 9.6 测试 6：单拍样本推理

操作：

1. 在样本列表中选择一个正常样本
2. 点击播放/推理
3. 再选择一个异常样本重复测试

预期结果：

1. 能收到 `BEAT` 响应
2. 波形图正常绘制
3. 预测标签正常显示
4. 置信度正常显示
5. 推理耗时正常显示
6. 告警级别会根据结果变化

建议至少测试以下两类：

1. 正常样本
2. 异常样本

### 9.7 测试 7：监测记录写入业务服务端

操作：

1. 在推理页选择当前病人
2. 完成一次样本推理
3. 观察是否触发保存监测记录逻辑
4. 回到病人管理页，查看该病人的监测记录

预期结果：

1. 推理完成后，业务服务端收到 `ADD_MONITOR_RECORD`
2. 病人历史监测记录中可以看到新记录
3. 记录的预测标签、置信度、来源、样本名称正确

### 9.8 测试 8：异常报警自动生成

操作：

1. 对测试病人播放一个异常样本
2. 等待推理完成并保存监测记录
3. 进入病人页报警列表或报警中心页查看

预期结果：

1. 若告警等级为 `warning` 或 `critical`，自动生成报警
2. 报警状态初始应为 `new`
3. 报警记录中病人编号、时间、预测标签、置信度正确

### 9.9 测试 9：报警中心查看与确认

操作：

1. 进入报警中心
2. 查看全局报警列表
3. 选中一条报警
4. 打开“查看报警详情”弹窗
5. 点击“确认报警”

预期结果：

1. 报警中心能显示全局报警
2. 详情弹窗能显示病人信息和报警信息
3. 报警确认后状态从 `new` 变为 `confirmed`
4. `confirmed_at` 和 `confirmed_by` 正确写入

### 9.10 测试 10：总览页统计联动

操作：

1. 完成几次推理
2. 产生至少一条报警
3. 返回总览页

预期结果：

1. 监测记录数量增长
2. 报警数量增长
3. 未确认报警数量变化正确
4. 最近监测记录和最近报警列表更新

### 9.11 测试 11：密码修改功能

操作：

1. 进入关于页
2. 点击“修改密码”
3. 输入旧密码和新密码
4. 提交修改
5. 退出客户端
6. 使用新密码重新登录

预期结果：

1. 修改密码成功
2. 新密码可以登录
3. 旧密码不能再登录

说明：

当前业务服务端使用 `SHA-256` 对密码进行哈希处理，并兼容历史明文密码自动升级。

### 9.12 测试 12：推理连接超时与自动重连

操作：

1. 正常连接香橙派边缘推理服务
2. 让香橙派上的 `edge_infer_service` 停止运行
3. 观察 Qt 推理页日志
4. 再重新启动香橙派上的 `edge_infer_service`
5. 继续观察 Qt 推理页日志

预期结果：

1. 连接断开后，Qt 能感知断开
2. 日志中出现自动重连提示
3. 重连采用递增退避延迟
4. 服务恢复后，Qt 能重新连接成功

### 9.13 测试 13：业务服务连接超时

操作：

1. 在登录页填写一个错误的业务服务地址或关闭业务服务端
2. 点击登录

预期结果：

1. 在超时时间内无法连接时，出现超时提示
2. 不会一直卡死在连接中

## 14. 结论

先把边缘端部署到香橙派，再进行系统联调，这个顺序是对的，而且是你当前阶段最合理的下一步。

因为你现在不是缺功能点，而是需要把“训练模型 -> 边缘推理 -> Qt 展示 -> 业务落库 -> 报警处理”这条完整链路跑稳。
