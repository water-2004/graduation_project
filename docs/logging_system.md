# 毕设日志系统说明

## 1. 为什么要加日志系统

建议加，而且应该尽早加。

对你这个毕设来说，日志系统的作用主要不是“炫技”，而是解决三个实际问题：

- 排查客户端和服务端的联调问题
- 记录推理服务的运行状态、连接状态和异常信息
- 方便给老师展示系统工程化能力

如果没有日志，后面一旦出现下面这些问题，会很难定位：

- Qt 客户端连不上边缘服务
- 服务端收到异常请求但界面只看到“失败”
- 推理服务运行中断，但控制台信息已经被刷掉
- 老师问“系统怎么做故障排查”时，没有明确回答

## 2. 本次实现的范围

这一版没有照搬参考项目 `F:\Python_Project\DaRenQueQiao_main` 的完整日志框架，而是做了一个更适合当前毕设阶段的轻量版本。

当前已覆盖：

- `edge_infer_service` 边缘推理服务
- `graduation_project_widget` Qt 桌面客户端

当前没有强行统一到 Python 训练脚本里，因为你目前最需要的是把运行链路先稳定下来。

## 3. 当前日志架构

新增了共享日志组件：

- [logger.h](F:/graduation_project/shared/logger.h)
- [logger.cpp](F:/graduation_project/shared/logger.cpp)

设计思路是：

- 用一个线程安全单例 `Logger`
- 同时输出到控制台和日志文件
- `WARNING` 及以上级别额外写入关键日志文件
- 服务端和 Qt 客户端共用同一套实现

当前层次可以理解为：

`业务模块 -> Logger -> 控制台 + 主日志文件 + 关键日志文件`

## 4. 日志文件位置

当前默认策略是：

- 日志写到“可执行程序所在目录”的 `logs/` 文件夹下

例如：

- Qt 客户端运行后：`.../graduation_project_widget.exe` 同级目录下会出现 `logs/`
- 服务端运行后：`.../edge_infer_service.exe` 同级目录下会出现 `logs/`

每个程序会生成两类文件：

- 主日志：`<app_name>.log`
- 关键日志：`<app_name>_critical.log`

例如：

- `graduation_project_widget.log`
- `graduation_project_widget_critical.log`
- `edge_infer_service.log`
- `edge_infer_service_critical.log`

## 5. 当前记录了哪些内容

### 5.1 服务端

当前服务端会记录：

- 服务启动
- 模型路径
- 监听地址和端口
- 客户端连接
- 会话读写失败
- 收到命令
- 推理成功结果
- 推理失败或非法请求
- 服务退出

### 5.2 Qt 客户端

当前 Qt 客户端会记录：

- 客户端启动和退出
- 连接服务器
- 断开服务器
- 发送 `PING`
- 发送 `PREDICT`
- 收到服务端响应
- 网络错误
- 协议解析错误
- 本地输入校验失败

## 6. 为什么没有直接照搬参考项目

参考项目里的日志系统更完整，包含：

- 模块级 logger
- UI 信号总线
- 回调机制
- UI 过滤规则
- 多路输出控制
- 单实例锁等扩展能力

这些功能本身没问题，但对你现在这个毕设阶段来说偏重了。

你当前最合理的做法是：

1. 先把统一日志基础打好
2. 保证客户端和服务端都能落盘
3. 后面如果老师要求更强的工程化能力，再继续扩展模块级日志和 UI 过滤

这比一开始就把系统写得很复杂更稳。

## 7. 你给老师汇报时可以怎么说

你可以这样表达：

> 为了提高系统可维护性与故障定位效率，我在毕设中增加了统一日志系统。当前日志系统采用轻量化设计，服务端与 Qt 客户端共用一套线程安全日志组件，支持控制台输出、文件持久化以及关键异常日志分流。这样在系统联调、网络通信异常、推理失败等场景下，可以快速定位问题来源，也为后续系统扩展提供了基础支撑。

如果老师继续追问“为什么要加”，你可以接着说：

- 网络通信是异步的，只看界面不够排障
- 边缘推理服务长期运行，必须保留历史运行记录
- 医疗场景相关系统更需要可追踪性和可维护性

## 8. 后续可以怎么扩展

如果你后面要继续增强，可以按这个顺序来：

1. 给 Python 训练脚本统一接入 `logging`
2. 给不同模块拆分独立日志文件，例如 `network.log`、`infer.log`
3. 在 Qt 中增加“查看日志文件”或“实时日志面板”
4. 增加日志级别筛选和日志清理策略

## 9. 当前结论

这个毕设应该有日志系统。

而且你现在这个阶段，最合适的不是上特别重的企业级方案，而是先有一套：

- 能统一写日志
- 能查客户端问题
- 能查服务端问题
- 能向老师说明工程化思路

当前这一步已经是合理且必要的。
