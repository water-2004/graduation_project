# 监测记录与报警模块运行说明

## 1. 模块作用

本模块用于在系统运行时自动保存监测结果，并在检测到异常心拍时自动生成报警记录。

运行完成后，你可以做到：

1. 在监测页做一次推理
2. 自动将结果写入业务服务端
3. 返回病人管理页查看该病人的监测记录
4. 如果结果异常，还能查看报警记录

## 2. 前置条件

需要保证以下程序可正常运行：

1. `business_service`
2. `edge_infer_service`
3. `graduation_project_widget`

## 3. 启动顺序

建议按以下顺序启动：

1. 启动业务服务端
2. 启动推理服务端
3. 启动 Qt 客户端
4. 登录业务服务端
5. 选择病人进入监测页
6. 连接推理服务并执行推理
7. 返回病人页查看记录

## 6. 使用步骤

### 6.1 登录并选择病人

1. 打开 Qt 客户端。
2. 在登录页连接业务服务端。
3. 登录成功后进入病人管理页。
4. 选择一个已有病人，或者先新增一个病人。
5. 点击“进入监测”。

### 6.2 执行推理

监测页支持两种方式：

1. 手动输入 187 维特征后点击“发送预测”
2. 加载样本列表并点击“播放样本”

### 6.3 自动写入业务记录

当推理成功后，Qt 客户端会自动：

1. 生成监测记录
2. 通过 `BusinessClient` 发送给 `business_service`
3. 由业务服务端保存到 `business_service.db` 的 `monitor_records` 表
4. 如果 `alert_level` 为 `warning` 或 `critical`，自动写入 `business_service.db` 的 `alerts` 表

你不需要手工点击“保存记录”。

### 6.4 查看历史记录

1. 从监测页点击“返回病人列表”
2. 回到病人管理页
3. 选中对应病人
4. 页面下方会自动刷新：
   - 监测记录表
   - 报警记录表

## 7. 数据存储说明

当前业务服务端的在线主存储为：

```text
business_service.db
```

其中主要业务表包括：

1. `patients`
2. `monitor_records`
3. `alerts`

字段设计分别对应：

1. 病人基础档案
2. 每次推理后的监测记录
3. 异常结果对应的报警记录和确认状态

如果数据目录中还存在旧版 `TSV` 文件，它们只在首次启动导入时使用，不再作为在线主存储。

## 9. 常见问题

### 9.1 为什么监测页有结果，但病人页没有记录

优先检查：

1. 业务服务端是否已启动
2. 是否已经先登录业务服务端
3. 当前监测页是否是从病人页选择病人后进入的
4. 业务服务端是否断开连接

### 9.2 为什么没有生成报警记录

只有当 `alert_level` 是下面两种情况时才会生成报警记录：

1. `warning`
2. `critical`

如果结果是 `normal`，则只保存监测记录，不生成报警记录。

### 9.3 删除病人后记录也没了，是不是 bug

不是。

当前系统设计就是：

删除病人时，同时删除该病人的监测记录和报警记录，避免产生孤立数据。
